# MRAD 2.0 — фактическая проверка

Дата: **16 ноября 2026**. База изменений: `cc9a0b3`. Целевая и установленная версия Arma Reforger / Workbench: **1.9.0.37**. Требования: [TZ_MRAD_2.0.md](TZ_MRAD_2.0.md).

Этот отчёт отделяет результаты выполненных запусков от сценариев, которые ими не проверяются. Компиляция, сравнение формул или проверка сетевых свойств не заменяют выстрел игрока из ADS в мультиплеере. Статус полной приёмки определяется таблицей AC ниже.

## Среда и воспроизводимость

Проверки выполнены установленными `ArmaReforgerWorkbenchSteamDiag.exe`, `ArmaReforgerServerDiag.exe` и `ArmaReforgerSteamDiag.exe`. Версия подтверждена журналами запуска. Использовались собственные процессы и отдельные профили. Уже открытый редактор пользователя не изменялся. Исходники установленной vanilla изучались через штатный Workbench API; они не включены в репозиторий.

Игровой addon — `MRAD`, GUID `61E9542E592789AF`. Диагностические сущности и расширения находятся только в отдельном `tools/qa/MRAD_QA`, GUID `CBA77A6A1C5E4B20`. QA addon не предназначен для обычного сервера: он создаёт тестовые сущности и завершает свой процесс после проверки.

Сохранённые [выдержки журналов и результаты](qa/2026-11-16/) содержат собственные маркеры MRAD. В manifest указаны SHA-256 полных исходных журналов; сами полные журналы остаются в изолированных профилях проверки. Из выводов удалены абсолютные пути команд запуска. Числа в таблицах ниже относятся к конкретным запускам, а не к сумме повторов одного теста.

### Что именно проверено для игровых расчётов

Снижение использует штатный `BallisticTable.GetHeightFromProjectileSource`; это не сторонняя физическая модель. Для заряженного native M21 при коэффициенте 1 результаты совпали с `GetAimHeightOfNextProjectile` на 100/300/700/1000 м. В тесте native M16A2 использован настоящий зарегистрированный suppressor: коэффициент 1.01 менялся на 0.8 и восстанавливался через его attributes. Source-расчёт и таблица MRAD изменяются; native next-projectile helper и helper начальной скорости этот attachment-модификатор не отражают. Эксперимент с фактически созданным выстрелом учитывается отдельно и не подменяется этим сравнением.

Запасной ветер ограничен игровым `ShellMoveComponent`, его `Mass`/`AirDrag` и гравитацией движка. Native predictor недоступен в проверенном headless runtime, поэтому там нужен этот путь. Схема интегрирования сверена с native predictor установленного World Editor. Неизвестные классы движения и непригодные параметры дают явное отсутствие данных. В интерфейсе остаётся пометка запасной модели. Результат 360 сравнений не обещает точность для произвольного стороннего projectile.

Погодный угол означает направление **откуда** дует ветер. Это прямо указано родными строками `AR-Editor_Attribute_WindDirection_Description` и `AR-Notification_EDITOR_ATTRIBUTES_WIND_CHANGED`. Шесть автоматических случаев проверяют проекцию и знак, включая взгляд вертикально. Детали и отвергнутые гипотезы находятся в [RESEARCH_RUNTIME.md](RESEARCH_RUNTIME.md).

### Сеть, JIP и граница ADS

Подтверждённый сетевой запуск `network-20261116T151544271791Z` использовал неизменный снимок исходников с SHA-256 `5c5a3394f51766fdecd0e692893f9a69034758acd33048b6a5920f33364caa98`; штатная проверка script checksum оставалась включённой. Клиенты разрешали реальные компоненты через их replication ID и сравнивали страницу, каждую строку таблицы, заголовок/статус и ticks прицела с независимым серверным снимком. Для таблицы сравнивались range/drop/wind/validity, числовые значения в сигнатуре форматировались до пяти знаков после точки. Передача данных и JIP подтверждены; render target блокнота в руках другого игрока, обычные действия перелистывания, передача предмета и положительный запрос поправки из ADS этим сценарием не проверяются. Подробности: [RESEARCH_OPTICS.md](RESEARCH_OPTICS.md) и [NETWORK.md](../tools/qa/NETWORK.md).

**Отдельный opt-in ADS сценарий полного PASS не получил.** В запусках `network-20261116T151645407367Z` и `network-20261116T152116174829Z` обе версии сетевых данных были получены, но ADS helper завершился по ограничению времени на стадии 3 — входе в native ADS. Во втором запуске владение персонажем клиентом подтверждено (`RplComponent.IsOwner=true`), однако native ADS не активировался; итог helper: `stages=2 actionDispatches=0 failures=1`. Поэтому успешный приём production RPC в ADS и доставка действия через реальный input listener не заявляются. Последующая opt-in правка fixture с публичным `SetWeaponADS(bool)` не имеет завершённого подтверждающего запуска. Физические клавиши/Shift, их переназначение и фактическое смещение попадания остаются отдельными непроверенными сценариями; **AC-11 и AC-12 не подтверждены**.

## Демонстрационная карта: отдельное замечание

Финальный `--showcase` запуск исходной `Worlds/ArlandTest2/GM_Arland.ent` (`runtime-20261116T153130065889Z`) загрузил и проверил **все пять размещённых блокнотов**: gadget есть, collider есть, headless RT отсутствует, `notebooks=5 failures=0`. Два исходных самостоятельных объекта с WeaponComponent дополнены обязательным SignalsManagerComponent; прежних ENTITY ошибок после правки нет.

**Весь showcase run не засчитан как PASS.** При закрытии процесса после завершения репликации штатный `SCR_BaseResupplySupportStationComponent` дважды пишет `needs a entity catalog manager!`. Строгий launcher сохранил `passed=false`, хотя процесс завершился с exit 0 и MRAD assertions прошли. Причина и исправление этого teardown замечания не подтверждены; ошибка не скрыта и не исключена из критерия. [Журнал](qa/2026-11-16/showcase.log), [результат](qa/2026-11-16/showcase-result.json). В поставленной vanilla также встречаются внешние Rally resource warnings и teardown resource reports; их отсутствие не заявляется.

## Известные границы

- Публичный найденный API позволяет определить projectile текущего магазина, но не отдельный старый патрон, оставшийся в патроннике после тактической смены типа боеприпаса. Поддержка этого частного состояния не заявляется.
- Значения прицела принадлежат его сетевому экземпляру и живут вместе с ним. Сохранение предметов через перезапуск сценария зависит от его persistence системы; глобальный JSON игрока не подменяет item state.
- Сторонняя оптика, переопределяющая camera/reticle hooks, требует отдельного адаптера или проверки. Штатные прицелы не заменяются глобально.
- Консоли как устройства и управление геймпадом не проверялись. Наличие project configurations и desktop компиляция не являются тестом на консоли.
- Старые ассеты и GUID сохранены. Отсутствовавшая физическая геометрия блокнота исправлена штатным box collider в prefab по native bounds модели; сам XOB не изменён. Полный физический сценарий броска/подбора игроком отдельно не проверен.
- Workshop не публиковался. Отправка исходников в GitHub не означает публикацию или прохождение всех AC.


Дополнительный `--native-fire` включает наблюдение настоящих native projectile событий; он считается успешным только при отдельном итоговом маркере с тремя выстрелами на каждое состояние и нулём ошибок. Подробности сетевого запуска: [tools/qa/NETWORK.md](../tools/qa/NETWORK.md).

Launcher проверяет завершение собственного процесса, итоговые маркеры и SCRIPT(E). Одного exit code 0 недостаточно. Для GUI дополнительно просматриваются ошибки ресурсов и реальные снимки окна. Неудачные диагностические эксперименты описаны в исследовании и не включаются в число успешных проверок.
