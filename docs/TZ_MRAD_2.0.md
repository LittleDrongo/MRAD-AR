## 1. Исходная формулировка заказчика (нормализованная)

> Мод устарел, хочу обновить его силами Claude. Нужно проанализировать мод и создать ТЗ.
>
> Мод реализует динамический блокнот с поправками на стрельбу. В игре уже есть префаб блокнота с render-texture и сырой набросок, который вводит туда данные.
>
> Как должно работать:
> - скрипт проверяет, какое оружие у персонажа в **1-м слоте оружия**, получает для него `BallisticTable`;
> - с оружия снимаются параметры `MuzzleComponent`, чтобы учитывать **текущий глушитель**, который вмешивается в баллистику;
> - скрипт считает поправки и выводит их игроку в блокноте.
>
> Формат записи в блокноте:
> ```
> Bullet (текущий заряженный патрон)
> Range - Bullet Drop (MRADs) - 4 mps Wind (MRADs)
> 100          0.7           0.2
> 200          1.2           0.4
> 300          1.7           0.6
> ```
> И так далее. Если строки дальности не помещаются на одну страницу — нужны экшены «следующая страница» / «предыдущая страница».
>
> Далее нужен компонент, чтобы мододел мог заменить ванильный на кастомный. Кастомный компонент прицелов 2D/3D должен изменять зероинг на **1 и 0.1 MRAD**. Для этого нужно забиндить клавиши в специальном разделе «Горячих клавиш» и выделить новую вкладку, где будут жить все настройки:
>
> | Действие | Клавиши |
> |---|---|
> | Поправка 0.1 вверх | `Arrow Up` |
> | Поправка 0.1 вниз | `Arrow Down` |
> | Поправка 0.1 влево | `Arrow Left` |
> | Поправка 0.1 вправо | `Arrow Right` |
> | Поправка 1.0 вверх | `Shift + Arrow Up` |
> | Поправка 1.0 вниз | `Shift + Arrow Down` |
> | Поправка 1.0 влево | `Shift + Arrow Left` |
> | Поправка 1.0 вправо | `Shift + Arrow Right` |
>
> При нажатии прицел должен менять зероинг на указанную угловую величину. Ранее заказчик вручную заполнял параметры, задавая массив положений с шагом 0.1 — это неудобно, и для ветра так поправку сделать не получается.

## 4. Требования

### 4.1 FR-1. Динамический блокнот поправок

**FR-1.1. Источник данных — оружие в 1-м слоте оружия.**
Блокнот — гаджет, поэтому в руках у игрока оружия нет. Скрипт обязан брать **оружие из первого слота оружия персонажа** (primary/weapon slot index 0), а не «текущее оружие в руках». Если слот пуст — показать локализованную ошибку, а не падать.

**FR-1.2. Учёт патрона.**
Заголовок и расчёт строятся по **текущему заряженному патрону** (магазин, который стоит в оружии). Нужны:
- человекочитаемое имя патрона для заголовка `Bullet: …` (локализовано, если есть строка);
- `IEntitySource` снаряда этого патрона для баллистического расчёта;
- устойчивость к оружию без магазина (гранатомёт/миномёт — по `GetDefaultMagazineOrProjectileName()`).

**FR-1.3. Учёт глушителя (MuzzleComponent).**
С оружия снимаются параметры текущего ствола/дульного устройства:
- коэффициент начальной скорости ствола;
- коэффициент скорости от надетого глушителя (статы оружия);
- факт наличия глушителя (для пометки в блокноте, опционально).
Итоговая таблица должна **отличаться** для «с глушителем» и «без» — это проверяемый критерий.

**FR-1.4. Формат таблицы (обязательный).**

```
Bullet: <патрон>
Range    Bullet Drop (MRADs)    4 mps Wind (MRADs)
100      0.7                     0.2
200      1.2                     0.4
300      1.7                     0.6
...
```

- три колонки, выровнены по левому краю/по центру, числа — **1 знак после запятой** (десятичный разделитель — точка, как в ТЗ заказчика);
- шаг дальности **100 м**;
- верхняя граница — максимальная дальность патрона/оружия (округление вниз до кратного 100), но не более разумного предела (предложение: 1500 м; вынести в настройку);
- строки, где баллистика не определена (`time <= 0`, `height <= 0`), **не выводятся**;
- заголовок ветра отображает **опорную скорость ветра** (по умолчанию 4 м/с) — значение из настроек, формат `<W> mps Wind (MRADs)`.

**FR-1.5. Расчёт снижения (Bullet Drop, MRAD).**
Снижение считается по ванильной баллистике для конкретного снаряда и коэффициента скорости (см. 5.1): высота прицеливания на дальности → угол → MRAD.
Требование: значения должны совпадать с ванильной таблицей поправок (допуск ±0.1 MRAD) при одинаковых входных данных.

**FR-1.6. Расчёт ветрового сноса (Wind, MRAD).**
Колонка — угловая поправка на **боковой (перпендикулярный) ветер** опорной скорости (по умолчанию 4 м/с). Знак: «+» — поправка вправо, «−» — влево (зафиксировать в документации мода; см. 5.3).
Если для снаряда нет ванильной таблицы ветра — использовать расчётный fallback (см. 5.3), результат не хуже ±0.2 MRAD от эталонной симуляции.

**FR-1.7. Страницы.**
- Число строк на страницу задаётся layout-ом (и настройкой); по умолчанию — сколько помещается при текущем кегле;
- **экшены на предмете**: «Следующая страница» и «Предыдущая страница» (user actions, видны только когда блокнот в руках и страниц > 1);
- переключение по кругу; индикатор `Страница N/M` в углу страницы;
- состояние страницы реплицируется (все видят одинаковую страницу).

**FR-1.8. Обновление.**
Пересчёт — при: смене оружия в слоте, смене патрона/магазина, смене глушителя, изменении настроек, открытии блокнота (взятии в руки). Не чаще, чем нужно; результат кэшируется по ключу (оружие, патрон, ствол, коэффициент, ветер, настройки).

**FR-1.9. Ошибки и пустые состояния.**
Локализованные сообщения: нет оружия в слоте, нет магазина, нет ствола, нет данных баллистики, нет данных ветра. Формат — существующий стиль `#MRAD_Error_*`.

### 4.2 FR-2. MRAD-зероинг прицелов

**FR-2.1. Совместимость типов прицелов.**
Компонент должен быть применим к прицелам, которые использует мод (2D-сетка и PIP/«3D»-оптика). В API 1.9 нет `SCR_3DOpticsComponent`: 2D — `SCR_2DOpticsComponent`/`SCR_2DSightsComponent`, PIP — `SCR_2DPIPSightsComponent` (см. Приложение A). Требуется 2 кастомных компонента-наследника (2D и PIP) с общим кодом поправок.

**FR-2.2. Шаг поправок.**
Поправки вводятся шагами **0.1 MRAD** и **1.0 MRAD**, отдельно по вертикали (вверх/вниз) и горизонтали (влево/вправо). Итоговое смещение — накопительная сумма шагов (а не выбор из массива положений).
Мододел, заменяющий ванильный компонент на кастомный, **не должен** вручную заполнять массив положений с шагом 0.1.

**FR-2.3. Клавиши (обязательно).**

| Действие | Клавиши | Шаг |
|---|---|---|
| Поправка вверх | `Arrow Up` | +0.1 MRAD |
| Поправка вниз | `Arrow Down` | −0.1 MRAD |
| Поправка влево | `Arrow Left` | −0.1 MRAD |
| Поправка вправо | `Arrow Right` | +0.1 MRAD |
| Поправка вверх | `Shift + Arrow Up` | +1.0 MRAD |
| Поправка вниз | `Shift + Arrow Down` | −1.0 MRAD |
| Поправка влево | `Shift + Arrow Left` | −1.0 MRAD |
| Поправка вправо | `Shift + Arrow Right` | +1.0 MRAD |

Все 8 действий **переназначаемы** игроком в меню «Горячие клавиши».

**FR-2.4. Поведение при нажатии.**
- Прицел меняет зероинг на указанную угловую величину; точка попадания смещается соответственно (вертикаль — дальность/превышение, горизонталь — вынос на ветер).
- Поправка действует, пока игрок смотрит в прицел (ADS), и на выстрел (не только визуально) — проверяется в мультиплеере.
- Ограничения: настраиваемые пределы (предложение ±50 MRAD по каждой оси); при упоре — без изменений + звуковой/текстовый отклик (опционально).
- Сброс поправок — отдельным действием (предложение: `Shift + R` или пункт в настройках; уточнить у заказчика).
- Индикация текущих поправок в HUD (опционально, но желательно): `0.0 / 0.0 MRAD`.

**FR-2.5. Хранение и репликация.**
Поправки привязаны к экземпляру оружия/прицела в рамках сессии; при смене прицела/оружия — свои значения. Изменения синхронизируются клиент ↔ сервер (авторитет сервера), чтобы попадания совпадали у всех.

**FR-2.6. Совместимость.**
- Ванильные префабы не изменяются: мододел сам ставит кастомный компонент вместо ванильного (или наследует префаб).
- Не ломать ванильные действия прицела (зум, подсветка сетки) и не конфликтовать с другими модами на оптику (ACE Scopes и т.п.) — минимум `modded`-классов.

### 4.3 FR-3. Раздел «Горячие клавиши» и настройки

**FR-3.1. Новая вкладка.**
В меню настроек, в разделе «Горячие клавиши» (Controls/Keybindings), должна появиться **новая вкладка мода** (рабочее название «MRAD»), в которой живут:
- 8 биндов из FR-2.3 (с отображением текущей клавиши и возможностью переназначить);
- параметры мода: опорная скорость ветра (по умолчанию 4 м/с), шаг/пределы поправок, число строк на страницу блокнота, показывать ли текущие поправки в HUD, режим ветра (опорный/текущий).

**FR-3.2. Ограничения и запасной вариант.**
Если публичный API 1.9 не позволяет добавить вкладку именно в ванильное меню Controls (это надо исследовать, см. R-8):

## 5. Предлагаемая архитектура

> Это рекомендация. Итоговые имена/структуру Claude может уточнить, но состав подсистем и контракты должны сохраниться.

### 5.1. Модель данных блокнота

**Получение оружия из 1-го слота** (`CharacterWeaponManagerComponent`):

- `GetWeaponsSlots(out array<WeaponSlotComponent> slots)` / `GetWeapons(out array<BaseWeaponComponent>)`;
- `WeaponSlotComponent` наследует `BaseWeaponComponent` → у слота есть `GetCurrentMuzzle()`, `GetCurrentMagazine()`, `GetWeaponEntity()`, `GetWeaponSlotIndex()`;
- фильтр: `GetWeaponSlotIndex() == 0` или `GetWeaponSlotType() == "primary"` (тип — строка, не enum);
- fallback: если слотов нет — `GetCurrentWeapon()` (на случай ручного оружия).

**Патрон и снаряд:**

- `weapon.GetCurrentMagazine()` → `BaseMagazineComponent`;
- `magazine.GetAmmoType(0)` (API 1.7+) — `ResourceName` патрона; fallback `muzzle.GetDefaultMagazineOrProjectileName()` (магазин или снаряд);
- `Resource.Load(rn).GetResource().ToEntitySource()` → `IEntitySource` (кэшировать по `rn`);
- заголовок: `MagazineUIInfo.Cast(magazine.GetUIInfo())` → `GetAmmoCaliber()`, `GetAmmoType()` + имя патрона из UIInfo; при отсутствии — имя ресурса.

**Глушитель / скорость:**

- `muzzle.GetBulletInitSpeedCoef()` — коэффициент ствола;
- статы оружия: `BaseWeaponStatsManagerComponent.GetMuzzleVelocityCoefficient(index, out float coef)` — коэффициент от надетого дульного устройства (глушитель: `SCR_WeaponAttachmentSuppressorAttributes.m_fMuzzleSpeedCoefficient`);
- `muzzle.IsMuzzleSuppressed()` — флаг для пометки;
- итоговый коэффициент = произведение (проверить, что движок перемножает именно так; см. R-3).

### 5.2. Рендер таблицы

- Не собирать таблицу одной строкой в `RichTextWidget`: нужны **колонки**. Два варианта:
  1. `GridLayoutWidget` с 3 колонками фиксированной ширины (соответствует клетчатой бумаге), строки — ячейки `TextWidget`; шапка и строки в отдельных ячейках; так делает ванильный `SCR_VisualisedBallisticConfig`/`SCR_BallisticTableComponent`;
  2. если Grid недоступен/тяжёл — 3 `TextWidget`-колонки, позиционированные по X, и обновление текста построчно.
- Шрифт: рукописный `.fnt` может быть не моноширинным → выравнивание колонок только через отдельные виджеты. Проверить `Bold` (SDF-only).
- Индикатор страницы — отдельный `TextWidget` (`Страница 1/3`).
- Размер RT = размер `RTTextureWidget` в layout (670×997); отдельного API размера нет.

### 5.3. Расчёт: drop и ветер

**Drop (MRAD):**

```c
float aimHeight, tof;
aimHeight = BallisticTable.GetHeightFromProjectileSource(distance, tof, source, initSpeedCoef, true);
if (tof <= 0 || aimHeight <= 0) continue;                    // за пределами баллистики
float mrad = SCR_Math.ConvertFromRadians(Math.Atan2(aimHeight, distance), SCR_EOpticsAngleUnits.MILLIRADIANS);
```

Допустимая альтернатива без `IEntitySource`: `BallisticTable.GetAimHeightOfNextProjectile(distance, tof, muzzle, true)` — она сама берёт состояние ствола, но **не** учитывает коэффициент глушителя (использовать только как fallback).

**Ветер (MRAD):**

- ванильная предрасчитанная таблица: `SCR_ProjectileWindTable.GetProjectileWindageData(source)` → `GetDataByAngle(angleRad, windSpeed: 10, initSpeedCoef)`; в возвращаемом массиве: `[3]` — азимутальная поправка в MRAD для **перпендикулярного ветра 10 м/с**, `[4]` — разница дальности для попутного/встречного (м);
- масштабирование на опорный ветер: `windMrad = baseMrad * (W / 10)`;
- ловушка: `GetDataByAngle` сравнивает `windSpeed`/`initSpeedCoef` на точное равенство и возвращает `null`, если значения не совпадают → нужен подбор ближайшей записи/интерполяция или собственный пересчёт;
- fallback без таблицы: `ProjectileMoveComponent.GetProjectileSimulationResult(...)` с `windSpeed` и численный поиск угла/сноса (как в моде `MortarWindTemplate/BallisticTablePlus`), либо собственная линейная аппроксимация;
- текущий ветер (если включён режим «текущий»): `World.GetTimeAndWeatherManager()` → `GetWindSpeed()`, `GetWindDirection()` (градусы), проекция на линию визирования; направление «откуда/куда» проверить эмпирически;
- знак и направление колонки зафиксировать в документации и проверить выстрелом.

### 5.4. Страницы и экшены

- Наследовать `SCR_DataDisplayGadgetComponent` (в 1.9 есть `GetNumberOfPages()`, `ChangePage(int direction = 0)`, `RpcDo_SyncPageChange(int)`, `m_iCurrentPageID`, `InitializeRenderTarget()`), либо воспроизвести её жизненный цикл в своём компоненте.
- Экшены: `SCR_ChangeDataPageAction` (в 1.9 переименован из `SCR_ChangeBallisticPageAction`) с `m_iStep = +1` и `-1`; в префабе добавить обе записи в `ActionsManagerComponent → UserActionContext → Actions`; `CanBeShownScript()` — только `GetMode() == EGadgetMode.IN_HAND && GetNumberOfPages() > 1`.
- `RplSave/RplLoad` + RPC для синхронизации страницы (как в ванили).
- Генерация данных: `MRAD_RangeCardData` (заголовок, массив строк, число страниц), пересчитывается в момент смены входных данных.

### 5.5. Зероинг

**Ограничение API (проверено):** произвольный угол зероинга в рантайме задать нельзя — `BaseSightsComponent.GetCurrentSightsRange()` только читает, `ForceSightsZeroValue(...)` работает **только в Workbench**. Ванильный зероинг — это выбранная запись из массива `Sights Ranges` префаба (`BaseContainer`, поле `Range`), которая либо поворачивает ADS-камеру (`EPZ_CAMERA_TURN`), либо сдвигает сетку (`EPZ_RETICLE_OFFSET`).

**Следствие:** «поправка» реализуется как **угловое смещение линии прицеливания**, накапливаемое в компоненте, а не как запись в массив зероинга.

Рабочий прототип (проверить в игре):

- кастомный компонент хранит `m_fElevationMrad`, `m_fWindageMrad` (стартовые значения — из текущего ванильного зероинга/префаба);
- переопределить `GetCameraLocalTransform(out vector matrix[4])` (публичный метод `SCR_2DOpticsComponent` в 1.9) и добавить в матрицу поворот на `pitch = m_fElevationMrad * 0.001` и `yaw = m_fWindageMrad * 0.001` (радианы → градусы для `Math3D.AnglesToMatrix`);
- альтернатива (как в моде ACE Scopes): переопределить `GetCameraAngles()` в **классе данных** компонента — но это состояние на весь префаб, а не на экземпляр, поэтому только если первый путь не работает;
- **критично для MP:** убедиться, что выстрел уходит именно по скорректированному направлению на сервере (проверка попаданий в MP). Если сервер не учитывает клиентское смещение — применить ту же поправку к направлению ствола в момент выстрела на обеих сторонах и синхронизировать состояние (`RplProp` + RPC), как в ванильном `SCR_2DSightsComponent` (`Replication.FindItemId(...)`).
- Если рабочий прототип не подтверждается в MP — зафиксировать в отчёте и предложить альтернативу (например, смещение `muzzle`-трансформа в момент выстрела через `modded BaseWeaponComponent`/`MuzzleComponent`).

**Шаги/пределы:** 0.1 и 1.0 MRAD, пределы в настройках, сброс отдельным действием.

### 5.6. Бинды и вкладка

**Факт:** в 1.9 в скриптах **нет** `InputManager.AddAction`/`GetActionIndex` — действия задаются конфигом движка (`ActionManager { Actions { Action … { InputSource … } } }`). Для своих действий:

1. отдельный `.conf` с описанием 8 действий (по образцу `Configs/System/chimeraInputCommon.conf` / `InputUserSettings.conf`);
2. `InputBinding b = GetGame().GetInputManager().CreateUserBinding();` → `b.GetCustomConfigs(list)` → добавить свой конфиг → `b.SetCustomConfigs(list)`; проверить, что действия появились (`GetActionCount/GetActionName`);
3. чтение: `AddActionListener("MRAD_ZeroingUp", EActionTrigger.DOWN, cb)` + `GetActionValue(...)` (модификатор Shift — отдельное действие `CharacterStanceModifier`/`pressed`-фильтр или отдельные комбо-бинды `InputSourceCombo`);
4. UI: `SCR_SettingsManagerKeybindModule` (`AddKeybindToActionByIndex`, `StartCaptureForAction`, …), категории меню — из `keyBindingMenu.conf`; новая вкладка — `SCR_SuperMenuComponent.GetTabView().AddTab(...)`;
5. если добавление в ванильное меню не подтвердится — запасной вариант FR-3.2.

## 8. Критерии приёмки и тест-план

### 8.1. Сценарии (обязательные)

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| AC-1 | Игрок с винтовкой в 1-м слоте берёт блокнот | Таблица для этой винтовки и её патрона; заголовок `Bullet: …` |
| AC-2 | Тот же ствол, надет/снят глушитель | Значения drop отличаются; в блокноте видна пометка о глушителе (если включено) |
| AC-3 | Смена патрона в магазине | Таблица пересчитывается |
| AC-4 | Смена оружия в 1-м слоте | Таблица пересчитывается |
| AC-5 | Оружия в слоте нет / нет магазина | Локализованная ошибка, без падения |
| AC-6 | Длинная таблица (много строк) | Появляются экшены «Следующая/Предыдущая страница», переключение по кругу, индикатор `N/M` |
| AC-7 | Второй игрок смотрит на блокнот | Видит ту же страницу (репликация) |
| AC-8 | ADS, нажатие `Arrow Up` ×10 | Поправка +1.0 MRAD (10×0.1), отображается в HUD/блокноте |
| AC-9 | `Shift + Arrow Right` ×3 | Поправка +3.0 MRAD вправо |
| AC-10 | Поправка на пределе | Дальше не растёт; есть обратная связь |
| AC-11 | MP: выстрел с поправкой | Попадание смещено на расчётную величину у стрелка и в мире |
| AC-12 | Смена клавиш в настройках | Новые клавиши работают без перезапуска |
| AC-13 | Перезапуск игры | Настройки и бинды сохранены |
| AC-14 | Другой мод на оптику (ACE Scopes) | Нет конфликтов/падений (или документированное ограничение) |
| AC-15 | Workbench World Editor | Нет инициализации RT в редакторе, нет ошибок в `script.log` |
| AC-16 | 100 переключений страниц/оружия | Нет утечек/падений, стабильный FPS |

### 8.2. Регресс

- ванильные прицелы без кастомного компонента работают как раньше;
- старые префабы карточек (`RangeCard_Notepad_AUTO.et`, статические карточки) не ломаются;
- showcase-миссия запускается, блокнот на сигнальной горке (см. `m_sDetails`) работает;
- логи компиляции чистые (см. `script.log`).

### 8.3. Доказательства в отчёте

Скриншоты/видео блокнота (2-3 оружия, с/без глушителя, страницы), фрагменты логов, таблица «факт vs ожидание» по AC, список изменённых файлов, инструкция проверки.

## 9. Риски

| Риск | Вероятность | Влияние | Смягчение |
|---|---|---|---|
| Зероинг нельзя корректно применить в MP (сервер не видит клиентское смещение) | средняя | высокое | Ранний прототип M3; fallback — поправка ствола на обеих сторонах + `RplProp` |
| Нет ванильных wind-таблиц у части снарядов | средняя | среднее | Fallback на симуляцию `GetProjectileSimulationResult` + кэш |
| Направление ветра («откуда/куда») неверно интерпретировано | средняя | среднее | Эмпирическая калибровка, тест 700–1000 м |
| Вкладку в «Горячие клавиши» нельзя добавить публично | высокая | среднее | Запасной вариант: своя страница настроек (FR-3.2) |
| Переименования API 1.9/1.10 ломают сборку | средняя | среднее | Проверка по локальной doxygen, минимум `modded` |
| Несколько экземпляров блокнота = лишние RT/draw calls | средняя | низкое | RT только в руках, освобождение, профилирование |
| `GetProjectileSimulationResult` работает только при включённом projectile debugging | средняя | высокое | Проверить; при ограничении — только ванильные таблицы + аппроксимация |
| Шрифт не моноширинный → «пляшущие» колонки | высокая | низкое | Колонки отдельными виджетами/Grid |

## Приложение A. Проверенные факты по API 1.9

Проверено по локальной doxygen установленного билда (`Arma Reforger Tools\Workbench\docs\ArmaReforgerScriptAPIPublic\html`), если не указано иное.

**Оптика и зероинг**

| Факт | Детали |
|---|---|
| `SCR_2DOpticsComponent` | существует; наследник `SCR_2DSightsComponent`; в 1.9 **нет** `SCR_3DOpticsComponent` — для PIP использовать `SCR_2DPIPSightsComponent` |
| `BaseSightsComponent.GetCurrentSightsRange()` | только чтение; возвращает `vector` (x — значение анимации, y — дистанция) |
| `BaseSightsComponent.ForceSightsZeroValue(vector offset, vector angles, vector turnOffset)` | существует, но **«only works in Workbench»** |
| `ForceSightsZeroValueEnablel(bool)` | отключение форсированного зероинга |
| `SCR_2DOpticsComponent.GetCameraLocalTransform(out vector matrix[4])` | публичный; точка приложения угловой поправки |
| `GetCameraPitchTarget()`, `GetCurrentCameraPitchOffset()`, `GetCurrentReticleOffsetY()`, `SetReticleOffsetX/Y()` | существуют (часть — protected) |
| Зероинг в префабе | массив `Sights Ranges` (`BaseContainer`, поле `Range`), тип — `SCR_EPIPZeroingType` (`EPZ_CAMERA_TURN`, `EPZ_RETICLE_OFFSET`) |
| Действия прицела | `WeaponOpticsZoomIn`, `WeaponOpticsZoomOut`, `WeaponToggleSightsIllumination` |

**Оружие/ствол/патрон**

| Факт | Детали |
|---|---|
| `BaseMuzzleComponent.GetBulletInitSpeedCoef()` | коэффициент начальной скорости ствола |
| `BaseMuzzleComponent.IsMuzzleSuppressed()` | флаг глушителя |
| `BaseMuzzleComponent.GetDefaultMagazineOrProjectileName()`, `GetMagazine()`, `GetMuzzleType()`, `GetUIInfo()` | существуют |
| `WeaponSlotComponent` / `CharacterWeaponSlotComponent` | существуют; `GetWeaponSlotIndex()`, `GetWeaponSlotType()` (строка `"primary"`/`"secondary"`) |
| `BaseMagazineComponent.GetAmmoType(int idx = 0)` | добавлен в 1.7; возвращает `ResourceName` патрона |
| `MagazineUIInfo` | `GetAmmoCaliber()`, `GetAmmoType()` |

**Баллистика/ветер**

| Факт | Детали |
|---|---|
| `BallisticTable.GetHeightFromProjectileSource(distance, out time, IEntitySource, initSpeedCoef = 1.0, bDirectFire = true)` | основной метод; `GetAimHeightOfNextProjectile(distance, out time, BaseMuzzleComponent, bDirectFire)` тоже есть |
| `SCR_ProjectileWindTable.GetProjectileWindageData(IEntity/ResourceName/IEntitySource)` | статический; читает таблицу из `ProjectileMoveComponent` |
| `SCR_ProjectileWindData` | `m_aValues`: `[0]` азимутальная поправка (MRAD, перпендикулярный ветер), `[1]` разница дальности (м, попутный), `[2]` угол встречи |
| `SCR_ProjectileWindTable.GetDataByAngle(angle, windSpeed = 10, initSpeedCoef = 1)` | точное сравнение аргументов (риск `null`) |
| `ProjectileMoveComponent.GetProjectileSimulationResult(initPosition, initSpeed, initElevationAngle, initAzimuth = 0, windSpeed = vector.Zero, targetHeight = 0, mustFallDown = true, maxSimulationTime = -1, maxHorizontalDistance = -1)` | возвращает конечную точку; может требовать projectile debugging |
| `World.GetTimeAndWeatherManager()` → `GetWindSpeed()`, `GetWindDirection()` | скорость (м/с) и направление (градусы) |
| `SCR_BallisticData.s_aBallistics`, `GetValues/SetValues/GetBallisticValuesForClosestRange` | кэш ванильных таблиц |

**UI/гаджеты/ввод**

| Факт | Детали |
|---|---|
| `RTTextureWidget` | `SetRenderTarget(IEntity)`, `RemoveRenderTarget(IEntity)`, `SetRenderView(IEntity, int)`; размера RT из скрипта нет |
| `SCR_DataDisplayGadgetComponent` | `GetNumberOfPages()`, `ChangePage(int direction = 0)`, `RpcDo_SyncPageChange(int)` (protected), `m_iCurrentPageID`, `InitializeRenderTarget()` (protected) |
| `SCR_ChangeDataPageAction` | 1.9: переименован из `SCR_ChangeBallisticPageAction`; `m_iStep`, `PerformAction`, `CanBeShownScript`, `CanBroadcastScript` |
| `SCR_GadgetComponent` | `GetMode()` (`EGadgetMode.IN_HAND` и др.) |
| `InputManager`/`ActionManager` | **нет** `AddAction`/`GetActionIndex`; есть `AddActionListener`, `GetActionValue`, `IsActionActive` |
| `InputBinding` | `CreateUserBinding()`, `AddBinding`, `GetCustomConfigs/SetCustomConfigs`, `StartCapture/SaveCapture`, `GetKeyCode` |
| Настройки клавиш | `SCR_SettingsManagerKeybindModule`, категории из `Configs/System/keyBindingMenu.conf`, вкладки — `SCR_SuperMenuComponent.GetTabView().AddTab(...)` |
| Локализация | `StringTable` + `WidgetManager.Translate("#ID")`, формат `%1..%9` |

**Изменения 1.9, влияющие на мод**

- `ElideText()` переехал из `RichTextWidget` в `TextWidget`;
- новые `Timestamp`/`DateTimeView`/`Duration` (риск конфликта имён в модах);
- `SCR_ELoiterItemID` → `SCR_EAnimationItemID`;
- `SCR_InventoryStorageManagerComponent.ValidateStorageRequest()` → `ValidateItemRequest()`;
- `SCR_ChangeBallisticPageAction` → `SCR_ChangeDataPageAction`.
