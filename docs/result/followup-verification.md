# MRAD 2.0 — повторная проверка после замечаний

## Обнаруженный дефект ввода

После коммита 356c843 игровая проверка показала: все восемь действий изменения поправок имели **keyboardBindings=0**. Вкладка настроек отображалась, но в ней не было назначенных стрелок. Прежний тест проверял существование строк, а не действительных назначений — результат был ошибочно засчитан.

Исправлено: восстановлен FilterPreset «click» в записях ввода без возвращения импульсного InputFilterDown. В изолированном игровом клиенте теперь четыре обычных действия имеют по одному назначению, четыре Shift-комбинации — по два назначения (левый/правый Shift). Проверено через InputBinding и скриншот реальной вкладки: [controls-fixed-2026-11-16.png](controls-fixed-2026-11-16.png). В QA добавлена обязательная проверка наличия назначений для всех восьми действий.

Повторный GUI-прогон: MRAD_SETTINGS_RESULT checks=164 failures=0; MRAD_RUNTIME_DONE validRows=12 failures=0; integration_pass=true.

## Демонстрационные карты

Автор удалил примеры MRAD_Rifle_M21_2D/PIP, но четыре объекта в трёх слоях карты всё ещё ссылались на несуществующие prefab. В слоях эти ссылки заменены на штатную M21 и отдельные prefab MRAD-прицелов. **Prefab самих винтовок не изменялись.**

Проверка демонстрационной карты: MRAD_SHOWCASE_RESULT notebooks=5 failures=0. В полном процессе остаются две ошибки штатного SCR_BaseResupplySupportStationComponent при уничтожении мира. Общая приёмка этой карты поэтому не отмечена как полностью успешная.
